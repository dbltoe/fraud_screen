Fraud Screen for Zen Cart

v1.0.3 (2026-10-06)
- Plugin ID is now 2464, the ID the Plugins Library assigned on 6 October
  2026. Earlier releases carried a placeholder the Library couldn't update, so
  Plugin Manager had no way to tell you about updates.
- No screening, code or settings changes. Upgrading is optional and only
  matters for update notices.
- Upgrading: put v1.0.3 beside v1.0.2 in zc_plugins/FraudScreen/ and click
  Upgrade in Plugin Manager; your settings and order history are kept. Zen Cart
  2.2.0 and later pick up the new ID by themselves. Zen Cart 2.1.x keeps the ID
  it stored at first install, so on 2.1.x also run:
    UPDATE plugin_control SET zc_contrib_id = 2464 WHERE unique_key = 'FraudScreen';
  Admin > Tools > Install SQL Patches adds your table prefix itself; in
  phpMyAdmin, add it to the table name (for example zen_plugin_control).

v1.0.2
- Fixed: the dry run did nothing. With the screen switched off and Log Every
  Screening Decision on, as the setup steps say, no order was scored or logged.
  It now logs every order with what would have happened (WOULD HOLD (dry run)
  or passed (dry run)) and holds nothing. Switched on, nothing changes.
- A Forum Support Thread button beside Read Me and GitHub in Plugin Manager.
- Upgrade in Plugin Manager; no settings change.

v1.0.1
- Fixed: a held order could be put straight back to its paid status. The hold
  was applied at NOTIFY_CHECKOUT_PROCESS_AFTER_ORDER_CREATE_ADD_PRODUCTS, before
  the payment module's after_process(), and a module that sets the order's
  status there (the Authorize.Net Accept.js module does) overwrote it. Screening
  now runs at NOTIFY_CHECKOUT_PROCESS_BEFORE_CART_RESET, after the payment module
  has finished, on every release from 1.5.8 through 3.0.0.

v1.0.0
- Initial release.
- Scores orders after creation against configurable signals: watched telephone
  numbers, email patterns, billing/delivery state and country mismatches,
  watched product models, and repeat use of a phone number or delivery address
  by a different customer.
- Holds orders reaching the threshold in a configurable order status and records
  the score and reasons in the order history.
- Registers its configuration group on the admin Configuration menu.
- Optional alert email and optional per-order decision logging.
- Screening never interrupts checkout; a false positive delays an order rather
  than losing the sale.
